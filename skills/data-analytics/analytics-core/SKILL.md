# Analytics Core

## 任務目標
- 本 Skill 用於：建立標準化的資料分析流程框架
- 能力包含：七階段流程、目標設定、價值實現、分析分類
- 觸發條件：需要進行資料分析專案時

## 適用場景
- 明確分析問題之前，需要先把目標和邊界定清楚
- 需要把分析流程拆成可執行的階段
- 需要判斷分析屬於戰略、運營、業務分析還是資料分析

## 操作步驟

### 七階段標準分析流程

```
┌─────────────────────────────────────────────────────────────┐
│                    資料分析全流程                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① 資料獲取 ──→ ② 資料清洗 ──→ ③ 資料處理 ──→ ④ 資料建模  │
│       │              │              │              │       │
│       ▼              ▼              ▼              ▼       │
│  明確目標        異常值處理      彙總轉換        統計/ML     │
│  採集資料        缺失值處理      格式變換        模型構建    │
│                                                             │
│  ⑤ 結果呈現 ──→ ⑥ 價值發現 ──→ ⑦ 價值實現                  │
│       │              │              │                      │
│       ▼              ▼              ▼                      │
│  視覺化展示      共同認知        業務轉化                    │
│  溝通協作        認可確定        迭代最佳化                    │
└─────────────────────────────────────────────────────────────┘
```

### 階段詳解

#### ① 資料獲取
**輸入**：分析目標（哪怕不明確）

**關鍵動作**：
- 明確資料來源（資料庫、API、檔案等）
- 確定資料範圍（時間週期、維度、指標）
- 理解資料口徑和計算方式

**輸出**：資料子集（物理或邏輯）

**注意事項**：
- 無目標則無從著手
- 目標要量化，如"產量從1萬下降到5千"而非"產量下降"

#### ② 資料清洗
**關鍵動作**：
- 異常資料處理（超出合理範圍的噪聲）
- 缺失資料處理（刪除、填充、插值）
- 資料一致性變換（單位、格式統一）
- 編碼替換（字元編碼、數值編碼）

**常見問題**：
```
- 數值欄位出現文字值
- 日期格式不統一
- 分類變數編碼混亂
- 重複記錄
```

#### ③ 資料處理
**關鍵動作**：
- 資料彙總（聚合統計）
- 資料轉換（行列變換、標準化）
- 特徵工程（構建新特徵）

**輸出**：適用於建模的乾淨資料集

#### ④ 資料建模
**方法分類**：
- **描述性分析**：趨勢、同比環比、維度拆分
- **預測性分析**：迴歸、分類、時間序列預測
- **因果分析**：AB測試、因果推斷

**常用演算法**：
```
描述統計：均值、方差、分位數、相關係數
趨勢分析：移動平均、指數平滑、趨勢線
預測模型：線性迴歸、決策樹、隨機森林、神經網路
降維方法：PCA、因子分析
```

#### ⑤ 結果呈現
**目的**：讓業務人員充分理解分析結果

**關鍵動作**：
- 選擇合適的視覺化方式
- 溝通是雙向的，確保理解一致
- 結論要清晰、有據可查

**呈現形式**：
- 圖表類：折線圖、柱狀圖、餅圖、散點圖
- 表格類：明細表、彙總表、交叉表
- 報告類：PPT、Word、分析報告

#### ⑥ 價值發現
**核心觀點**：分析師和業務人員的"共同認知"

**關鍵動作**：
- 從分析結果中提煉業務價值
- 與業務人員驗證和確認價值點
- 達成對分析結論的一致認可

**常見價值型別**：
```
業務最佳化：效率提升、成本降低
增長機會：使用者增長、收入增長
風險預警：異常識別、風險預測
決策支援：策略建議、方案對比
```

#### ⑦ 價值實現
**特點**：通常由業務人員控制，但需要分析師深度參與

**關鍵動作**：
- 跟蹤業務落地執行情況
- 驗證分析結論與實際效果的偏差
- 迭代最佳化，持續改進

**反饋閉環**：
```
分析結論 → 業務理解 → 業務執行 → 結果反饋 → 下一輪分析
```

### 分析目標設定

#### 目標來源
| 來源 | 適用場景 | 特點 |
|------|----------|------|
| 業務方發起 | 業務對發展有疑問希望透過資料提升 | 需求可能模糊，需要深入需求分析 |
| 資料部門發起 | 有完善的指標監控體系 | 更全面客觀，但需瞭解業務 |

#### 合格目標的特徵
1. **業務視角**：折射業務痛點
2. **資料支援**：有資料可支撐分析
3. **量化表達**："下降5%"比"下降"更清晰
4. **具體指標**：體現在可測量的指標上

**反面例子**：
- "為什麼最近業務不好？"（模糊）
- "我想知道運營效果如何？"（不量化）

**正面例子**：
- "為什麼全廠2018年Q1產品X產量從1萬下降到5千？"
- "XX業務轉化率從15%提升到20%"

### 分析分類體系

#### 按問題型別
| 型別 | 目標 | 視角 | 資料來源 |
|------|------|------|----------|
| 戰略分析 | 解決公司方向問題 | 宏觀 | 內部+競品+行業 |
| 運營分析 | 解決實際運營問題 | 微觀 | 內部為主 |

#### 按服務物件
| 型別 | 發起方 | 交付物件 | 效率 |
|------|--------|----------|------|
| 業務分析 | 業務部門 | 業務部門 | 較高 |
| 資料分析 | 資料部門 | 業務/管理層 | 需要深入溝通 |

#### 按分析範圍
| 型別 | 時間視窗 | 關注點 |
|------|----------|--------|
| 行業分析 | 1年以上 | 商業模式、發展趨勢 |
| 公司分析 | 1年內 | 業務診斷、決策建議 |
| 部門分析 | 半年內 | 職能範圍內診斷 |
| 業務環節分析 | 實時/短期 | 具體環節最佳化 |

### 分析師能力要求

#### 業務能力
- **微觀**：瞭解業務運營、公司發展方向
- **宏觀**：把握行業方向、預測未來變化

#### 資料能力
- **技術**：SQL/Python/R、機器學習、視覺化工具
- **通用**：指標體系、資料關係、因果推斷

#### 軟能力
- 溝通能力：雙向溝通，確保理解一致
- 邏輯思維：結構化分析、歸納演繹
- 同理心：站在業務角度思考
- 影響力：讓分析結果被接受和採納

### 資料分析三元論

#### 勢（行業環境）
- 行業特性：是否適合資料分析
- 公司資料環境：資訊化水平、資料文化

#### 道（分析框架）
- 業務模式：越簡單越容易出成果
- 分析框架：體系化、結構化
- 需求穩定：深入研究的基礎

#### 術（分析方法）
- 定性與定量：確定分析目的
- 指標創新：好的指標能準確反映問題
- 整體與個體：大處著眼，小處著手
- 大膽假設，小心求證：快速驗證最可能的原因

## 注意事項
- **分析前必須有目標！目標！目標！**
- 過程不是單向的，發現問題可跳回前一階段
- 過程是迴圈的，上一終點是下一起點
- 不是每個階段都必須，根據實際情況調整
- 分析師與業務人員密切合作貫穿全程
